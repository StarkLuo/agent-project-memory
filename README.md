# Agent Project Memory

[English](README.en.md) · [Agent 安装流程](INSTALL.md) · [MIT](LICENSE)

让 AI coding agents 在跨会话开发中记住**项目目标、当前状态、关键决策和证据**，而不是反复读取聊天记录。

这是从真实研究工程中提炼的轻量协作框架：可审查的 Markdown 记忆、按任务加载的原生 skills，以及只依赖 Python 标准库的安全安装器。支持 Codex、Claude Code 和 DeepSeek Harness（DSH）；不绑定模型，不运行后台服务，不需要 API key。

快速导航：[安装](#给-agent-一句话) · [完整使用指南](#usage-guide) · [常用话术](#prompt-cheatsheet) · [给 AI 的带用户使用指南](#agent-coaching) · [宿主适配](#宿主适配与实际边界) · [升级与恢复](#安全合并升级与恢复)

## 给 agent 一句话

在**目标工程**中，把下面的话发给 agent：

> 请从 https://github.com/StarkLuo/agent-project-memory 下载框架到目标工程之外，读取 INSTALL.md，按其中流程为当前工程安装 research 配置。我授权合并当前 agent 的用户级规则、工程规则并安装项目级 skills；保留我的所有现有规则与记忆。随后读取真实工程，结合我已说明的目标填写初始 memory；只有关键目标或约束缺失时再问我。先检查安装预览，不要仅创建占位文件就结束，不要发布我的工程或启动实验。

这是一条**给具备文件和 shell 权限的 agent 的工作指令**，不是 GitHub URL 自动执行机制。宿主的权限审批、工作区信任或重载提示仍然适用。

安装器处理文件与冲突；agent 负责理解代码、询问目标、填写事实。直接运行安装命令只生成框架与明确标记的占位记忆，不会调用 LLM 或假装完成语义初始化。

## 手动安装

要求 Python **3.10+**；下载可用 Git 或 GitHub ZIP。安装过程离线、不安装依赖。

```bash
git clone https://github.com/StarkLuo/agent-project-memory.git

# /path/to/project 是已有目标工程，不是刚下载的框架目录。
python3 agent-project-memory/install.py --project /path/to/project --agent codex --global-rules --dry-run
python3 agent-project-memory/install.py --project /path/to/project --agent codex --global-rules
```

Windows 可将 `python3` 换成 `py -3`。路径含空格时加引号。首次默认 research 配置；通用软件工程可加 `--profile core`。重复 `--agent` 可同时适配多种宿主：

```bash
python3 agent-project-memory/install.py --project /path/to/project --agent codex --agent claude --agent dsh --global-rules
```

然后让 agent 读取目标工程的 `.agents/skills/initialize-memory/SKILL.md` 完成初始化，最后检查：

```bash
python3 agent-project-memory/install.py --project /path/to/project --check --strict
```

`--strict` 要求三个热文件不再是初始化占位；未使用的 knowledge 允许保留占位。检查通过只代表结构条件满足，不证明项目事实正确。

## 三层职责

```text
用户级规则                 跨项目约定，保留你的个人设置
目标工程/
├── AGENTS.md              工程规则、记忆入口和任务路由
├── CLAUDE.md              仅 Claude：导入 AGENTS.md
├── .agents/
│   ├── skills/*/SKILL.md   原生任务流程
│   └── project-memory/    安装清单；本地备份被 Git 忽略
├── .claude/skills/         仅 Claude：自动生成的适配副本
└── project_memory/        只保存记忆，不保存 skills 或安装状态
    ├── 00_project_brief.md
    ├── 01_current_focus.md
    ├── 02_repo_map.md
    ├── knowledge/         架构、决策、实验、运行、问题、术语、文献
    └── archive/           历史原文，不默认读取
```

不把全部文件塞进每次上下文。三个热文件保存当前工作集；knowledge 按相关主题查阅；archive 只在追溯历史时读取。

## 使用指南：从第一次介绍工程到长期协作

最常见的节奏是：**第一次把工程背景讲清楚 → 每个新会话先了解进度、等待指示 → 正常开发与研究 → 结束前记录交接记忆 → 用一段时间后整理记忆**。

你不需要每次记住 skill 名称，也不用手动填写全部 Markdown。描述意图即可，让 agent 选择合适流程。下面的话术是示例，不是必须逐字输入的命令；这些流程依靠宿主加载规则和模型理解，不是后台关键词触发器。若 agent 没有按预期处理，可明确要求读取对应的 `.agents/skills/<name>/SKILL.md`。

### 1. 初始化：把你知道的尽量讲清楚

安装框架通常只需做一次；初次填写记忆也不是每次新建聊天都要重做。安装后，你可以连续输入一大段背景，不必先整理成规范文档。如果内容很长，可以分几条发送，先说“我还没讲完，等我说开始整理后再初始化”。

尤其接手复杂遗留代码时，尽量把**与当前工程有关、你已经知道的内容**都告诉 agent。它们往往包含代码中看不出的历史原因、约束和踩坑。信息越充分越有帮助，但不要求你先读懂整个仓库；未知部分可以由 agent 检索，不需要用猜测填空。不要粘贴密钥、账号口令或无关敏感信息。

可以自然描述以下内容，不必逐项填表：

- **要达成什么**：项目解决什么问题，期望的效果、成功标准，以及暂时不做什么。
- **你眼中的目录地图**：哪些文件是真实入口，各目录负责什么；哪些是第三方代码、历史遗留、实验副本或已经废弃的入口。
- **已知运行方式**：你实际用过的命令、配置、输入输出位置和环境前提。区分“以前能用”和“最近已经验证”。
- **当前做到哪里**：已完成的改动、尚未完成的部分、最近结果、活跃问题，以及下一个最想解决的任务。
- **为什么变成现在这样**：曾试过哪些路线，失败发生在什么条件下，哪些设计出于兼容或资源限制而保留。
- **不能随便动什么**：接口、数据划分、评价协议、依赖环境、第三方目录、正在运行的任务，以及时间或资源预算。
- **哪里不确定**：比如“我记得入口在这里，但不确定是否还在用”。用户描述可以提供线索，不必被记录为已经由代码证实的事实。

例如，安装完成后可以直接说：

```text
请根据下面的背景和当前工程初始化 project_memory。先只读梳理代码、填写记忆，
不要开始实现或运行训练；我说不准的地方请核对，不要直接当作确定事实。

我想把这个旧工程改造成可重复运行的数据处理与训练流程。第一阶段先让现有
流程稳定复现，暂时不要重写模型。最终希望新人只看文档就知道怎么运行。

我目前知道 scripts/ 里有启动脚本，src/ 里是主要实现，configs/ 放配置。
历史上有两个入口，旧入口可能还被某些脚本调用，请帮我查清楚。
legacy/ 暂时不能删，有些逻辑可能还在使用。outputs/ 是已有运行产物，不能覆盖。

我最近改过数据读取，但还没有提交；完整训练是否通过我不确定。
当前最想解决的是入口混乱和恢复运行容易出错。先不要增加依赖，也不要改评价协议。
其他我没讲到的结构请从代码中补充；目标或关键约束仍缺失时，再集中问我。
```

如果你几乎不了解工程，可以换成：“请先只读梳理当前仓库，告诉我真实入口和主要模块，结合我下面描述的目标建立初始记忆；无法确认的地方标为待确认。”AI 能补查文件与调用关系，但不能仅靠代码猜出你的真实目标、业务取舍或可接受成本。

**初始化完成时，应该得到的是可用的交接材料，而不只是创建了一堆文件：**

- 项目概览说明目标、总路线和边界；当前焦点说明状态、阻塞和下一步；仓库地图能带你找到实际入口。
- 必要的历史原因、架构细节、已验证命令进入对应 knowledge，未涉及的知识文件允许暂时留空或保留占位。
- agent 简要说明哪些来自你的描述，哪些经过文件核对，哪些尚不确定，并只追问真正影响目标或执行边界的问题。
- 三个热文件已完成初步填写，可用 `--check --strict` 做结构检查；检查不能替代事实核对。

输入可以很长，**热记忆仍应短**。完整讲述的价值在于让 agent 提炼、分层存储和保留关键证据，不是把原话全部塞进 `01_current_focus.md`，更不是每次会话都读完整个仓库。

### 2. 每个新会话：先接手，再等待你的指示

你习惯的两轮启动方式很适合这个框架：先让 agent 恢复上下文，看到它的摘要后，再发本轮具体任务。

最简话术：

> 请了解当前进度，等待我的指示。

希望边界更明确时：

> 请先阅读当前工程的规则和热记忆，按需核对与当前状态有关的代码、配置或已有日志，简要说明目标、已完成事项、阻塞和待核实内容。当前只接手，不修改代码或 memory，不启动、恢复或终止任务；答复后等待我的下一条指示。

对应流程是 `start-new-session`。agent 应按需读取概览、focus 和 repo map，而不是默认全读 knowledge、archive 或所有 skills。涉及代码时核对分支和未提交改动；涉及运行时只在访问范围允许的情况下核对实际状态，不能把上次记录的“运行中”直接当作现在仍在运行。

**“等待我的指示”是本轮的停止条件。** 即使 memory 写着下一步要改代码、旧会话曾授权继续，当前明确要求等待时，也应在交接摘要后结束这一轮，等你发下一条任务，不自主推进旧计划。

看到摘要后，可以纠正误解：“刚才提到的 A 已完成，现在先看 B。”若此时仍不希望写文件，可先只纠正会话理解，等正式任务或会话结束时统一记录。

### 3. 日常协作：像平常一样开发，不用手动调度所有 skills

完成接手后，直接描述本轮想做的事。日常的交互式 AI 开发（vibe coding）仍由你决定方向，memory 负责承接上下文，不替你作目标选择。

一个容易执行的请求会说清**本轮目标、允许修改的范围，以及怎样算完成**。例如：

> 这轮只修复数据读取在空输入时的异常，不改接口和训练策略。请定位真实调用链，完成最小修复，用已有入口做必要验证，并记录会影响后续接手的稳定变化。

任务需要时，agent 再读取相关 skill：

| 你正在做什么 | 相关流程 | 应保留什么，何时保留 |
| --- | --- | --- |
| 一般实现、修复完成 | `close-session` | 本轮已授权工作产生的入口变化、验证范围、阻塞与下一步，局部回填 |
| 构思或发展研究 idea | `brainstorm-ideas` | 从可探索的线索出发，寻找有意义的差异、改进或新叙事；不以绝对原创为门槛 |
| 检查方法新颖性 | `check-method-novelty` | 核对最接近论文的真实机制和证据，区分表面相似与实质重复，给出有界主张 |
| 调研论文、比较研究路线 | 形成可复用结论后使用 `add-literature` | 在已授权记录范围内按主题保存来源、结论、分歧、适用条件；单纯读论文不自动写入 |
| 分析实验结果 | `review-experiment` | 先判断运行是否有效、比较是否公平、证据支持到哪一层；需要记录且有授权时写台账 |
| 规划实验或消融 | `plan-experiment` | 假设、固定项、预算与停止条件；计划不能写成已运行、已取得收益 |
| 讨论或设计架构 | 按需查架构与决策；稳定回填由 `close-session` 处理 | 已确认的设计与理由进入决策，已实现结构才写成实现事实；修改模型链路时才使用 `modify-backbone` |
| 运行、监控或恢复正式实验 | `run-experiment` | 在授权对象和预算内记录运行身份、状态、产物与恢复入口，不因查看结果自动重跑 |
| 定位训练异常或验证改动 | `diagnose-training` / `run-minimal-train` | 区分诊断与修复，记录实际检查过的范围，不把最小运行通过当作效果提升 |

研究相关流程需要 research 配置；core 配置不会凭空提供这些 skills。架构讨论本身没有必要强行匹配一个“改模型”的流程。

**自动选用 skill，不等于自动把每句话写进 memory。** 普通项目维护可以记录已授权工作产生的稳定变化；只读分析、随口建议、未采纳方案和未完成调查，不应自动变成既定事实或决策。纯讨论中希望保留内容时，直接说“请把本次结论记录到 memory”；希望不写时，说“这轮只讨论，不修改文件或 memory”。

如果你希望研究过程也有明确的自动沉淀范围，可以在开始相关任务时说明：

> 本轮调研、实验分析或架构讨论形成可复用结论后，请按相关 skills 局部更新 memory。明确区分已确认事实、我已采纳的决策、候选方案和待验证假设，不记录逐条聊天过程，不因此启动新实验。

记录的**完成状态**要准确：有代码不等于运行通过，运行通过不等于效果更好，指标改善也不直接证明提出的机制成立。值得保存但尚未确认的想法可以作为有来源、有边界的候选，不必删除，也不能升级成事实。

### 4. 结束前：记录 memory，给下一轮留下可接手状态

准备关闭对话、切换任务或换工具时，可以说：

> 记录 memory，方便跨平台接手。

更完整的版本：

> 请把本轮稳定变化记录到 memory，方便新会话或另一台机器接手。这次做局部回填，
> 不做全局重排。记录完成和未完成的部分、实际验证范围、未提交改动、阻塞、下一步，
> 以及相关日志和产物入口。替换直接相关的过期状态，保留证据和运行身份。
> 如果任务仍在运行，只记录本次实际核实的状态及观察时间，不重启或终止它。
> 更新后说明改了哪些文件，还有什么未核实，然后结束这一轮。

这对应 `close-session`，**不是** `rebalance-memory`。agent 应更新相关记录并刷新直接关联的索引，而不是把整段聊天追加成一个越来越长的日志。没有稳定变化时，可以明确说明无需写入。

结束前重点检查：

- 下一位 agent 能否区分“已完成”“只写了实现但未验证”“仍待决定”和“被中断”。
- 已知可运行命令是否注明前提；未测试的命令是否只是建议，而不是被记成验证过的入口。
- 关键运行是否有主机、run id、代码/配置身份、最后观察时间和日志/checkpoint/结果位置；无权访问的远端应标记未核实。
- 未提交或未跟踪的改动是否被提醒保留；新会话不能假设 Git HEAD 就等于实际工作区。
- 新任务和旧任务的关系是否明确：暂时切换不等于旧任务完成，被搁置的工作应有恢复入口。

可以等 agent 报告写入完成后再关闭对话。若对话意外中断，下一位 agent 可以结合现有 memory、工作区差异与日志重建状态，不必重新初始化或清空记忆。

### 5. 跨会话、跨工具、跨机器：记忆可携带，但不会自动同步

“跨平台接手”包含几种不同情况：

| 场景 | 你需要确保什么 |
| --- | --- |
| 同一工程、同一机器，新开聊天 | 新会话打开正确目录，读取已有规则与记忆；不用重新安装或初始化 |
| 同一机器，换一种 agent 工具 | 给新宿主补齐原生规则/skill 适配；复用同一份 `project_memory`，不再创建第二套事实副本 |
| 另一台机器、远端服务器或新的 checkout | 把对应代码、规则、skills 与 memory 同步过去；另行准备环境、数据、checkpoint 和运行产物，重新核对绝对路径及运行状态 |

**写 memory 不会自动执行 Git commit、push、复制文件或同步云盘，也不会搬走运行中的进程。** 这些操作需要单独的同步方式和相应授权。同步到 Git 时先检查忽略规则与内容是否敏感；未提交和未跟踪代码也必须纳入交接考虑，不能只传 Markdown。

通常应一起携带经过审查的项目级 `AGENTS.md`、`.agents/skills/`、`.agents/project-memory/manifest.json`、`project_memory/`；使用 Claude 时还包括其项目入口和适配 skills。不要把本地备份、个人全局规则、凭据或大型运行产物不加区分地提交。不同机器的用户级规则按需安装，不能假定它们随工程自动同步。

跨机器时优先在记忆中提供项目相对路径，必须使用绝对路径时注明主机和用途。记忆描述的是“在哪能找到证据”，不是证据文件本身。接手端找不到数据、缓存或 checkpoint 时应报告缺失，不能静默从头跑一个不同实验。

若新会话要做另一方面的改动，可以这样切换：

> 请先了解当前进度并等待。本轮之后我要处理可视化导出；之前的数据读取任务先保留为未完成，不要将它标记完成或自动继续。待我给出具体修改要求后再动手。

同时开多个会话时，尽量划分文件和任务范围，指定一个会话汇总更新共享 memory，避免几个 agent 同时覆盖同一份 focus。正在运行的作业与实验目录也应有唯一操作方；本框架没有自动合并并发写入的能力。

### 6. 用一段时间后：整理记忆，不是清空历史

可以每周检查一次，但“一周”只是个人使用节奏，框架没有定时整理任务。更实用的触发信号是：热文件越来越难读、当前状态彼此矛盾、同一内容反复出现、已完成任务仍占据焦点，或者项目路线已明显变化。

简单话术：

> 请大幅度整理 memory。

更明确的版本：

> 请按 rebalance-memory 对当前记忆做一次较彻底的整理：先核对当前目标、入口和状态，
> 再压缩热文件，把暂时用不到的细节移入合适的 knowledge 或 archive，并刷新引用。
> 保留关键决策的理由、失败条件、实验身份和证据来源；不要把“未验证”改成“无效”。
> 不删除运行产物，不修改业务代码，不为整理启动实验。最后说明修正了哪些冲突、
> 内容迁到哪里、热文件体量如何变化，还有哪些事实无法核实。

这里的“冷记忆”不是回收站：仍有复用价值的架构、决策、实验和运行方法放进相应 knowledge；仅供历史追溯的原文放进 archive。热文件留下当前工作集和必要导航。归档后仍能按需找到，但不应每次接手都加载。

整理应先判断事实是否有效，再判断文字能否压缩。短文件也可能过期，长文件也可能包含不可丢失的证据。brief / focus / repo map 的 2000 / 4000 / 5000 字符是提醒值，不是硬性截断指标；不需要追求固定压缩比例。

验收时看三个结果：仅靠热文件能否正确接手；活跃问题、决策和索引是否一致；迁移后的历史事实与引用是否仍可追溯。**“大幅整理”不授权删除 checkpoint、日志或数据，也不代表可以改写历史实验结果。**

### 7. 常见遗漏与恢复办法

- **记忆写错了**：指出具体条目和正确依据，让 agent 局部修正其主要位置及相关索引。保留历史观察的适用时间，不把过去失败改成从未失败。
- **换了目标或路线**：明确告诉 agent 新目标、取代了什么、哪些约束继续有效。通常更新 brief、focus 和决策即可，不用重新运行初始化或清空历史。
- **接手摘要不对**：先确认打开的是正确工程、分支和工作区，memory 是否同步；再检查宿主是否读取了规则与 skills。不要第一反应就是删掉记忆重建。
- **AI 没有自动记下来**：重要交接显式说“更新 memory”，并要求列出实际修改文件。自动选用流程不是可靠的后台保存服务，聊天中的口头总结也不等于文件已写入。
- **文档说有结果，但文件找不到**：区分历史记录与当前可复现资产。标注产物缺失及恢复前提，不凭目录名臆造结果，也不自动重跑。
- **想长期调整行为**：跨项目偏好放在用户级规则，工程特有约定放在项目 `AGENTS.md` 的受管理区块外；不要把规则、临时请求和项目事实混写进 focus。不要修改受管理区块哈希来绕过升级冲突。
- **想知道是否整理好了**：让 agent 给出修改文件、状态依据、迁移去向与未确认项，不只看“已更新”三个字。重大决策和实验结论值得人工抽查。

### 常用话术速查

| 意图 | 可以直接说 | 应有的边界 |
| --- | --- | --- |
| 首次填记忆 | 根据我的背景描述和真实工程初始化 memory，关键缺口再问我 | 保留已有事实；不开始开发或训练 |
| 分批介绍工程 | 我会分几条介绍，等我说开始整理再初始化 | 先收集理解，不提前落盘 |
| 新会话接手 | 请了解当前进度，等待我的指示 | 只读接手，摘要后停止 |
| 日常实施 | 完成这项修改并做必要验证，记录稳定变化 | 限本次目标、范围和预算 |
| 只讨论 | 这轮只分析，不修改代码或 memory | 不因匹配 skill 就写文件 |
| 沉淀研究结论 | 将本次文献/实验/设计结论记录到对应 memory | 保留来源，区分事实、候选、决策和假设 |
| 关闭对话 | 记录 memory，方便跨平台接手 | 局部回填，不自动同步或全局整理 |
| 切换工作方向 | 保存当前任务的恢复入口，下轮先做另一项任务 | 旧任务不自动标记完成或继续执行 |
| 周期维护 | 请大幅度整理 memory，保留证据并说明迁移位置 | 先核对再压缩，不删除实际产物 |
| 修正过期记忆 | 按这些新证据修正相关 memory 和索引 | 定点修正，不无关重写全库 |

<a id="agent-coaching"></a>

### 给 AI：如何带用户开始使用

如果你是帮助用户安装或使用本框架的 agent，请把本节当作使用解释，不当作额外执行权限。先遵守用户本轮要求和目标工程的规则；用户说等待、只读或暂不记录时，不从历史计划推导继续执行权限。

安装并初始化后，不必把整份 README 复述给用户。用简洁语言教会四件事：第一次可以完整讲背景；新会话可以先“了解进度，等待指示”；结束前说“记录 memory”；积累一段时间后说“整理 memory”。用户给长背景时，负责提炼和核对，不要求用户先整理成表格。

每次按任务加载适用 skill，沿用已有上下文与授权，避免重复询问已知信息。记录时说明真正写了哪些文件、哪些事实有依据、哪些仍未验证；无稳定变化时可以不写。跨平台时提醒同步代码与必要资产，不承诺仅凭 memory 就能恢复环境和运行。

用户需要操作指导时，给出当前场景最相关的话术和一个下一步即可。这个框架的目的，是让用户更自然地持续协作，不是要求每轮对话都完成一套固定仪式。

## Skills

| 配置 | Skills | 用途 |
| --- | --- | --- |
| core（4 个） | initialize-memory、start-new-session、close-session、rebalance-memory | 初始化、接手、局部回填、明确授权的整理 |
| research（共 13 个） | core + plan-experiment、review-experiment、run-experiment、diagnose-training、run-minimal-train、modify-backbone、add-literature、brainstorm-ideas、check-method-novelty | 实验设计、执行、证据审查、训练、文献、构思与新颖性核对 |

research 源自研究工程，但不包含任何具体模型、数据集、私有路径或实验结果。`modify-backbone` 的不变量来自目标工程知识，不把原工程的维度或训练策略外推。

“更新 memory”是局部替换当前状态；“整理/压缩 memory”才进行全局维护。审查流程不意味着启动流程中的实验；已有授权无需逐步重复确认，也不扩展到新对象或新预算。

## 宿主适配与实际边界

| 宿主 | 用户级规则（仅 `--global-rules`） | 工程入口 | 项目 skills |
| --- | --- | --- | --- |

这里的“全局”是**用户级指令文件**，不是修改厂商 system prompt。正确文件名是 `AGENTS.md`，不是大小写不同的 `AGENTS.MD`。

原生路径依据核对于 2026-09-18：[Codex 规则](https://learn.chatgpt.com/docs/agent-configuration/agents-md)、[Codex skills](https://learn.chatgpt.com/docs/build-skills)、[Claude memory](https://code.claude.com/docs/en/memory)、[Claude skills](https://code.claude.com/docs/en/skills)、[DSH 规则源码说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/context/agent-instructions/README.md)、[DSH skills 源码说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/skill/skill-filesystem/README.md)。DSH 仍处于 developer preview；禁用对应插件的自定义 preset 不会因安装文件而自动启用能力。

安装器总是生成 `.agents/skills/`；Claude 另生成等价副本，不依赖符号链接或 Windows 管理员权限。副本由安装器管理，不应单独修改；本地定制会在升级时报告冲突，检查也会发现两边不一致。已存在的同名用户级 skills、嵌套规则、宿主策略及上下文大小限制仍可能影响实际加载。安装后核对宿主技能列表与规则来源；必要时重开会话。

## 安全合并、升级与恢复

- `--dry-run` 不写文件、目录、安装状态或备份。
- 规则使用带哈希的 managed block（受管理区块）；区块外原文逐字节保留。要长期定制规则，写在区块外。区块内被修改时停止，先由 agent/维护者比较并合并，不强行覆盖。
- skills 使用安装清单中的基准哈希识别定制；定制冲突在写入前停止，未跟踪的同名内容不会被默默接管。
- 已有 `project_memory` 正文不覆盖。没有 `--force` 清空记忆的开关。
- 覆盖或删除前备份原文件。项目备份在 `.agents/project-memory/backups/`；全局备份在对应宿主目录的 `.agent-project-memory-backups/`，**不会复制个人全局规则到项目仓库**。
- 每个文件原子替换，但多个目录/文件并非一个事务。磁盘故障或并发修改可能留下部分写入：根据输出的备份检查并恢复，再重试。不要同时运行多个安装器。
- 拒绝受管理文件或其工程内父目录的符号链接；不改变权限策略、API 配置、模型选择、插件设置或业务代码。

升级：在框架仓库检查并拉取所需版本后，针对工程重新执行相同安装命令，先 `--dry-run`。已安装的 agent/profile 会保留，新增 `--agent` 是增量安装；不通过省略参数卸载宿主，不自动降级 research 为 core。需要更新用户级规则时再次显式带 `--global-rules`。

安装器不理解原有自然语言规则的语义冲突；agent 必须审查现有约定与新增区块，不能把“文件合并成功”当成“规则已经一致”。Codex 的非空 `AGENTS.override.md` 会遮蔽同层 `AGENTS.md`，安装器会提示并停止，交由使用者明确处理。

本机隔离演练可以加 `--user-home /path/to/sandbox-home`；该选项忽略实时宿主 home 环境变量，不修改 `$HOME` 或配置环境变量。

## 旧版迁移

原来的 `project_memory/skills/*.md` 不再需要。先检查当前规则与活跃记忆的引用，再执行：

```bash
python3 agent-project-memory/install.py --project /path/to/project --agent codex --remove-legacy --dry-run
python3 agent-project-memory/install.py --project /path/to/project --agent codex --remove-legacy
```

这只删除已知 v2.0.0 的**未修改跳转文件**，先备份且要求对应原生 skill 已安装；原始长技能正文或定制跳转会阻止迁移。旧 `add-experiment` 的工作由 `review-experiment` 的记录阶段承担。识别出的旧 `.framework.json` 一并移出记忆目录，安装状态改由 `.agents/project-memory/manifest.json` 管理。历史归档中的旧路径可以保留为历史事实，不继续充当当前入口。

## 隐私与限制

框架没有遥测、云同步或自动提交。agent 为填写记忆读取的文件仍会受其宿主/模型的数据政策约束；不要让 agent 读取不必要的密钥或敏感数据。`project_memory` 可能包含内部目标、机器路径和实验结果，公开业务仓库前必须单独审查，必要时加入自己的忽略规则。

本项目验证的是安装器和生成文件；尚不宣称已在三个宿主上完成真实模型会话的端到端验证，也不保证模型永远遵守 Markdown 指令。权限控制应使用宿主实际的 sandbox/approval 配置，不能用此框架替代。

## 维护本框架

正文唯一来源是 `skills/`，记忆占位来源是 `templates/project_memory/`，规则来源是 `templates/*-rules.md`。不要把真实项目记忆或凭据复制进模板。修改安装器后用隔离目录验证预览、重复安装、已有记忆保留、冲突、备份、core/research 与宿主适配，并检查新 skills 的 frontmatter 和安装后链接。

本框架有意保持简单：没有向量库、MCP 服务、自动训练调度或模型 API 封装。只有真实使用暴露了需要，才增加相应机制。
