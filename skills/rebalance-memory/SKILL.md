# 周期维护 memory

## 范围与入口

先读三个热文件：[brief](../../../project_memory/00_project_brief.md)、[focus](../../../project_memory/01_current_focus.md)、[repo map](../../../project_memory/02_repo_map.md)。
沿其引用检查活跃决策、问题、运行入口及主题索引；只补读受影响正文，不默认全读 knowledge 或 archive。
文件很短也可能过期；体量、重复、相互矛盾和检索困难均可作为维护依据。

## 先核对，再压缩

1. 区分用户目标/授权、实现事实、运行观察、研究解释、待验证假设和历史背景。
2. 核对冲突条目的适用版本、数据、时间和来源。用户最新确认决定目标；代码与产物证明实际行为。不能只按“最新日期”选结论。
3. 对高影响矛盾，读取已有配置、源码或结果定位原因；不为整理启动训练、重新评价或改变研究方案。缺失证据标为待核实。
4. 已后置问题移出当前阻塞；历史负结论保留适用前提，不能外推到已改变的架构或协议。

## 整理职责

- brief：稳定研究目标、总路线和成功标准。
- focus：当前任务、阻塞、最近观察、接下来 1–3 步、停止事项与必要导航。
- repo map：真实高价值入口和关键调用关系。
- 长期解释按职责进入 knowledge；仅有历史价值的原文进入 archive。先保存唯一历史信息再替换热文件。
- 优先维护受影响索引；不为统一格式重写所有冷区正文，不重编号历史实验。
- 压缩不能把“尚未证明”变成“无效”，不能丢失 run 身份、不变量、反例、失败条件或证据来源。

## 整理后验收

- 仅靠热文件能确定当前目标、阻塞、下一步与代码入口，且没有互斥的当前状态。
- 热文件引用的活跃问题/决策与正文一致；迁移后的导航和引用仍可定位。
- 事实主要记录位置明确；不可用产物标注“历史证据存在记录，但当前不可直接复现”，不伪造验证。
- 比较字符数/读取成本并检查信息覆盖。参考提醒值：brief 2000 字符、focus 4000 字符、repo map 5000 字符；它们不是硬性截断线，不靠拉长单行或丢证据达标。
- 交付说明迁移位置、修正的冲突、前后体量及未核实事项。归档原文不是当前指令，默认接手不读。
