# 运行与恢复实验

从 [当前焦点](../../../project_memory/01_current_focus.md) 和 [运行手册](../../../project_memory/knowledge/13_runbook.md) 定位相关任务，读取实际脚本/配置。使用既有 runner、队列和日志，不另搭调度系统。

## 启动前

- 确认目标、允许的数据/实验组合、设备/主机、GPU/RAM/磁盘/时长预算、完成与停止条件。已有明确授权直接沿用，不反复询问。
- 记录 run id、命令、代码快照或相关 diff/未跟踪文件、配置/数据身份及评价协议；优先复用现有元数据。
- 检查已有进程、输出目录、checkpoint、完成标记和缓存状态，避免重复运行或覆盖产物。
- 对未知成本或新链路，按需先使用最小运行；已有适用验证不重复执行。缺少会显著影响成本或正确性的选择时先确认。

## 运行、监控与恢复

- 启动只覆盖已授权实验；使用现有长期运行机制，保存日志和主机/session/PID 标识。PID 还需结合命令核对，不独凭数字操作进程。
- 监控步数是否推进、真实错误、非有限值、资源和预算。停止按事先条件执行；仅“监控”授权不包含任意重启或终止。
- 续跑先核对进程确已结束、checkpoint 可用、代码/数据/配置及优化器/RNG 恢复约束一致。完成的任务只分析，不重复启动。
- 身份不匹配、缓存缺失或无 checkpoint 时明确失败原因；不静默绕过校验、降级从头训练、删目录或扩充实验组合。
- 运行失败或取消时保留必要证据与恢复入口，状态标为 failed/interrupted/cancelled；进程正常退出仍需检查既定产物后才能标为完成。
- 多人或多 agent 协作时，GPU 作业和同一输出目录指定唯一操作方；变更共享源码前核对正在运行的任务。

## 交接

记录观察日期、主机/run id、最后确认状态、日志/checkpoint/结果入口和下一步。未连接远端时明确未验证实时状态。
运行完成交给结果审查；已有完成标记不自动证明效果成立。项目 memory 只保存短状态与引用，逐步日志留在运行产物中。
