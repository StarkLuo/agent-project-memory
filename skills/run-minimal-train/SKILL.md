# 最小运行验证

从 [运行手册](../../../project_memory/knowledge/13_runbook.md) 的相关入口与 [仓库地图](../../../project_memory/02_repo_map.md) 定位真实命令，再核对脚本实际默认值；不臆造命令。

## 选择足够的验证层级

| 影响范围 | 优先验证 |
| --- | --- |
| 文档、shell、配置解析 | 对应静态检查或已有 dry-run，避免有副作用的导入 |
| 数据入口或时间/坐标变换 | 最小真实样本的范围、shape、dtype、语义 |
| 前向/推理路径 | 单 batch 前向及输出合法性 |
| loss、梯度、冻结或递归状态 | 最小 backward，检查相关梯度和不应变化的状态 |
| 优化器、checkpoint、续训 | 极小步数及必要的保存/恢复一致性 |

只执行与本次风险相关的层级，不机械逐级跑满。优先复用已有入口；新增测试文件遵守用户与项目约定。
GPU 验证前确认设备占用、输出隔离和资源预算；不得干扰已有训练或复用会覆盖的目录。
通过后停止；仅有新改动、失败或未解决风险才扩展检查。功能通过不构成质量或速度优势。

## 失败与交付

保留第一真实错误、实际命令、运行身份和必要日志；不吞异常、加静默 fallback 或通过改协议绕过问题。
在已授权修复范围内定位并验证；仅要求诊断时返回原因与下一步，不擅自实施修复。
报告通过到哪一层、关键证据、资源观察和未覆盖部分；不只输出失败信息。
