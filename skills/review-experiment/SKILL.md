# 审查与记录实验

先从 [实验台账](../../../project_memory/knowledge/12_experiment_ledger.md) 的索引定位相关实验；已有有效审查可复用，补查新增或有冲突的证据。

## 审查阶段

1. 确认 run 身份与完整性：实际命令、代码快照或相关 diff、配置、数据范围、checkpoint、日志和完成状态。目录名不是配置证据。
2. 确认比较有效性：baseline、训练预算、checkpoint 选择、评价帧覆盖、mask/crop/timestamp、亮度映射和指标聚合是否一致；核对是否发生训练/验证/测试泄漏。
3. 结合指标、逐场景差异、关键可视化和异常日志判断结果；不要以单个 loss 或主观观感消除证据矛盾。只读取支持当前判断所需的产物。
4. 分层给出结论：运行是否有效、比较是否公平、在什么范围有收益/退化、是否支持提出的机制。允许“混合结果”“证据不足”或“仅功能通过”。
5. 小于波动的差异不写成确定优势；机制结论需要相应干预/消融，不能把相关性当成因果贡献。

## 记录阶段

用户要求记录或项目会后维护规则已授权稳定回填时才落盘；只读审查不因此扩大写入范围。
记录到 [实验台账](../../../project_memory/knowledge/12_experiment_ledger.md)，至少保留：
- 日期/run id 与实际代码、配置、数据身份；
- 假设、改动、固定项及评价协议；
- 关键观察、来源路径及有限结论；
- 复现状态、适用边界和后续动作。

同主题可以综合结论，但各 run 的事实、配置差异与原始观察保持可追溯。新解释通过补充或替代关系关联旧结论，不覆盖历史事实、不重编号。
运行失败、取消或缺产物有恢复价值时记录运行状态；无需伪造研究结论。刷新受影响索引；仅在当前任务/决策改变时局部同步 focus 或 decisions。

## 交付

说明有效性、主要证据、结论边界、是否已记录和仍待确认的事项。审查过程中不自动重训、修改评价协议或启动新消融。
